## Global Constraints

- **Không** import `content-marketing/video-social/**`, `content-media-image.provider`, `content-media-replicate.provider`.
- **Không** job `social_*`. S2 chỉ `cine_keyframe` trên `q.image`.
- **Không** bịa URL ảnh. Thiếu key → job `failed` + `error_class=auth` (vẫn OK).
- Secret provider chỉ env (`PTT_VD_LEONARDO_API_KEY`, `REPLICATE_API_TOKEN`). **Không** cột/API field `api_key`/`secret` trên `vd_providers`.
- HTTP user **không** await generate: `201 { id, status: 'queued' }`.
- Job status CHECK: `created`,`queued`,`running`,`succeeded`,`failed`,`cancelled`,`stale`.
- Retry ≤3 chỉ `transient` / `rate_limit`.
- Caps: `crm_vd.admin` view/create; S2 fallback `ai_admin` view cho SC-15. Job enqueue: `crm_vd.project` create **hoặc** `crm_content` write.
- Flag cinematic vẫn bắt buộc cho enqueue (đã có `assertCinematicEnabled`).
- **UI bắt buộc:** SC-15 trang admin + SC-02 bảng job + nút enqueue. Không ship S2 chỉ API.
- Import graph: `video-sop` ↛ `social-ffmpeg` / `social-video.service`. `social-studio.util` vẫn được (S1).

```ts
export type VdQueue =
  | 'q.text' | 'q.image' | 'q.video.kling' | 'q.video.runway'
  | 'q.enhance' | 'q.media' | 'q.notify';

export type VdJobStatus =
  | 'created' | 'queued' | 'running' | 'succeeded' | 'failed' | 'cancelled' | 'stale';

export type VdJobRow = {
  id: number;
  project_id: number;
  shot_id: number | null;
  queue: VdQueue;
  job_type: string;
  status: VdJobStatus;
  error_class: string | null;
  attempt: number;
  idempotency_key: string;
  input_json: Record<string, unknown>;
  output_json: Record<string, unknown>;
  created_at: string;
  updated_at: string;
};

enqueue(input: {
  projectId: number;
  queue: VdQueue;
  jobType: string;
  payload: Record<string, unknown>;
  idempotencyKey: string;
}): Promise<VdJobRow>;
```

- Trùng `idempotency_key` → trả job cũ (không tạo mới).
- Handler S2: only `cine_keyframe` registered. Unknown `job_type` → `failed` `validation`.
- Retry: if handler throws with `error_class` `transient`|`rate_limit` and `attempt < 3`, re-queue via `setImmediate`. After 3 → `failed`.
- HTTP:
  - `POST /api/v1/vd/projects/:id/jobs` header `Idempotency-Key` required; body `{ queue, job_type, payload? }` → **201** `{ id, status: 'queued' }` (do not wait drain).
  - `GET /api/v1/vd/projects/:id/jobs` → `VdJobRow[]`
  - `GET /api/v1/vd/jobs/:id` → `VdJobRow`
  - Guard: same create/view as S1 project (`crm_vd.project` / `crm_content` fallback).
  - Missing header → 400 `idempotency_key_required`.
  - `assertCinematicEnabled` on POST.
